This is the separately authorized Mnemosyne exchange slice. No universal
persistence, scientific generator, Athena Phase 2.5, WELD migration or Hephaestus
consolidation was started. Mnemosyne preserves records and attributed history;
it does not determine scientific truth or absorb detailed domain results.

CONTRACT AND SERIALIZATION
New EvidenceExchange supplies the explicit version-1 profile:
- mnemosyne-record/1 for standalone reference/observation/review/assessment/change;
- mnemosyne-exchange/1 for a bounded history snapshot and manifest.
The normative field, encoding, digest and consistency rules are documented in
software/modules/mnemosyne/EXCHANGE_V1.txt.

Jackson databind plus its JDK8 and Java-time modules are reused from the existing
repository ecosystem. No new serialization framework was adopted. These are the
only permitted production dependencies of Mnemosyne, confined to the exchange
codec; core scientific records remain free of serialization annotations and
scientific domain dependencies. Private uncertainty mix-ins define explicit tags.
The existing architecture tests now enforce this narrower exchange-only exception.

Existing public signatures and domain schemas are unchanged. The authorized
manifest contract adds SNAPSHOT to ScientificReference.Kind. New public contracts:
EvidenceExchange.RecordType; RecordDigest(reference,type,sha256);
Manifest(schema,reference,creationActivity,createdAt,parent,records);
Snapshot(manifest,history); snapshot/encode/decode/read/write operations and
standalone record encoding/decoding/content digests. Snapshot equality explicitly
compares all four history maps; Phase 1 EvidenceHistory equality is unchanged.

ROUND-TRIP AND IDENTITY GUARANTEES
Every reference namespace/ID/version, scalar spelling (including 62.140), unit,
uncertainty choice/bounds/error, availability, reason, limitation, timestamp,
policy/process reference, outcome and provenance link is preserved. No scientific
value is normalized numerically during serialization. Unknown remains unknown.
Unavailable values remain absent. NOT_MEASURED retains no observation/review.

Immutable record reference identity is independent of its content digest. Record
digests include the complete canonical record envelope and all fields, including
timestamps and schema/type. Canonical objects sort keys by Java String UTF-16
order; arrays retain order except manifest/history membership, which sorts by
reference tuple. UTF-8 compact JSON, no BOM/newline, standard JSON escaping,
no Unicode normalization, UTC Instant strings and explicit null optionals.

Exact transport bytes have a separate optional caller-computed SHA-256; whitespace
changes that digest but not record content. A referenced raw artifact's digest
is neither the record digest nor the exchange digest. Historical Athena and
Prometheus hashes/identities are not changed. The local codec uses the JDK SHA-256
primitive because importing a domain hash wrapper would reverse dependencies.

MANIFEST / INTEGRITY
Manifest identifies schema, snapshot ID/version, creation activity/time, optional
parent and member references/types/digests. Each actual record appears once in the
body, not again in the manifest. manifestSha256 covers all manifest fields and
member digests. Membership and every record digest are checked on read. A snapshot
is a pinned view, not a globally current or true state.

Internal observation/review/assessment/change references must resolve within the
snapshot. External source, subject, method, policy, proposition, agent/activity,
artifact and parent-snapshot references are intentionally not fabricated or copied
into the common model. Their resolution is a separate boundary.

Checksums protect integrity, not authentication: replacement of an entire document
and all its checksums requires a trusted external expected identity/digest to
detect. No signatures, cross-document immutable reservation service or global
conflict store is claimed. The bounded reader/writer limit is 16 MiB. Files are
written CREATE_NEW with checked I/O exceptions; there is no catalog, append store,
overwrite policy, distributed transaction or crash-durability claim.

REFERENCE RESOLUTION
ReferenceResolver<T> uses injected Authority<T> methods supports, find, identityOf
and verify. Results distinguish RESOLVED / UNAVAILABLE / CONFLICTING / UNSUPPORTED.
Identity is derived from returned content and compared with the requested kind,
namespace, ID and version. No record/verification payload accompanies a failure.
Verification separately lists the ARTIFACT references whose bytes were checked.
RESOLVED with an empty verification list proves linkage only.

Athena ScientificReferenceResolution:
- Reads the existing source-review reservation via DesignGrammarJsonCodec.
- Resolves source, receipt, artifact and historical review references to the
  authoritative SourceDecision/SourceReceipt/SourceReview.
- Reprojects and compares exact exchanged observation/review fields.
- Delegates source verification to the host through SourceVerifier. Acceptance
  invokes the existing source importer's raw-byte reparse verification; Athena
  gains no reverse source-I/O dependency and implements no new parser.
- Rejects a forged parsed value even when its preserved raw hash still matches.
- Historical resolution does not undo review withdrawal or confer current approval.

Prometheus ScientificReferenceResolution:
- Requires an existing GeneratedEvidenceRegistry file and reopens that authority
  to repeat payload/raw artifact verification. A miss creates no directory/store.
- Resolves source/artifact/receipt/specification/context to GeneratedEvidenceEntry,
  including its QuantumEvidence, EvidenceIdentity and lifecycle records.
- Requires explicit PRIMARY or VALIDATION_AUXILIARY selection; no role inference.
- Verifies result/specification/role correspondence, exact projection, and that
  source path/hash is covered by the registry's verified artifact list.
- Does not register, run, retry, change acceptance or make auxiliary evidence reusable.

Resolver authorities are trusted injected code. The foundation cannot independently
prove that a malicious plugin performed its claimed verification. Ordinary lookup
I/O failures are UNAVAILABLE; explicit domain integrity failures are CONFLICTING.
No unsupported namespace/version falls back to a weaker identity match.

HISTORICAL RECONSTRUCTION
Temporary-file acceptance exchanges one unchanged observation, independent reviews,
all five assessment outcomes, a later supersession and a withdrawal. Reloaded maps
and manifest are semantically equal and canonical re-encoding is byte-identical.
Tests preserve both knownAt and effectiveAt queries and historical assessments.
The actual frozen source path also round-trips and resolves a later-withdrawn review
without making it currently admissible for a new Athena binding.

Reconstruction validates all changes before assessments, using explicit times rather
than file order. A working set whose assessment was already inadmissible at its
recorded/known time cannot be published; no automatic repair or invented event
ordering occurs. Same-time withdrawals apply inclusively. This is an explicit
exchange consistency restriction; Phase 1 objects and historical domain files
are not migrated or rewritten.

FAILURE COVERAGE
Tests reject unknown exchange/record versions, malformed references, numeric enums
and coerced numeric identifier/scalar text, numeric timestamps, null record data,
unknown fields, duplicate JSON keys, duplicate conflicting identities, missing
internal records even after integrity metadata is recomputed, corrupted body or
manifest, returned resolver identity/version mismatch, unsupported namespaces/
versions, source-projection forgery and changed raw artifacts. Existing source and
registry authorities remain responsible for domain verification semantics.

LIMITATIONS / RECOMMENDED PHASE 3
- This is a bounded exchange profile, not a universal repository or persistence
  format selected for production scale. Large scientific payloads stay external.
- JSON interoperability is documented and golden-tested in Java; no independent
  non-Java implementation or exhaustive Unicode conformance corpus was run.
- Checksums are not signatures. Namespace trust and expected snapshot identity
  must be supplied externally; cross-snapshot conflicts need consumer handling.
- Resolvers cover pinned existing paths and explicit roles, not global namespace
  discovery. Authority validation is point-in-time, not a distributed atomic read.
- External method/policy/proposition/context semantics remain domain references;
  a successful lookup is not proof of scientific truth or current admissibility.
- Strict known-time consistency rejects ambiguous/backdated inconsistent history
  rather than guessing insertion order. Detailed event ordering is not invented.

Recommended Phase 3, only after review: a bounded cross-snapshot reconciliation
and admission contract that checks expected parent/reference/digest, preserves
branches and disagreements, and reports conflicts without silently merging them.
Use frozen exchange fixtures and current authorities first. Do not choose a
persistence backend merely to implement that semantic check.
