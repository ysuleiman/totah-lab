PUBLIC CONTRACT / COMPATIBILITY

DesignKnowledge supports athena-design-knowledge/2 for qualified planning/evaluation.
The existing SCHEMA constant remains athena-design-knowledge/1 for historical replay;
QUALIFIED_SCHEMA explicitly opts into the stricter path. Production callers seeking these
new guarantees must supply schema 2. Legacy unqualified data is never silently upgraded.
Existing constructor signatures for Evidence, Criterion, Hypothesis, Finding and Decision
remain as overloads. Legacy fixtures and tests pass unchanged; missing new JSON fields default
to null/empty. Record components and serialized shape are additive changes; record-pattern or
strict external JSON consumers need review/recompilation. New enum values are additive.
No scientific backend identifier, frozen Phase 2.1 fixture or historical report was renamed.

Evidence adds Qualification and Value. Qualification contains method/endpoint/system/conditions/
unit/value-kind semantics, ScientificStatus, exact subject DesignState, reviewer reference and
an explicit uncertainty description. Source and version remain the existing Reference.
Value is either finite ordered inclusive numeric bounds or a qualitative category, never both.
Requirements specify accepted evidence kinds/statuses and exact semantics, independently.
Hypotheses add explicit evidence requirements, optional ReviewedBinding and unresolved observations.
Criteria add a requirement, accepted interval/category, versioned policy and policy-source references.
Findings retain the raw evidence reference. withEvidence appends immutable observations;
evaluate derives dimension-wise findings; withEvaluation validates them again on snapshot creation.

COMPARABILITY / CLAIM BOUNDARIES

Exact method name/version/parameters, endpoint ID/version, system ID/version, condition map,
unit and quantitative/qualitative kind must agree. No implicit unit conversion, method aliases,
endpoint substitution, potency inference or global evidence-quality score is implemented.
Evidence must be reviewed, in the hypothesis context, of an explicitly permitted class/status,
and applicable to the original exact design state. A reviewed transfer is separately required
for a reordered/renamed parent. Unbound requirements cannot be silently ignored.
SCREENING_ONLY can satisfy only a policy explicitly accepting that status. It cannot satisfy
VALIDATED_REFERENCE by conversion or ranking. Source type restrictions also apply to raw
observations behind a supporting evaluation, preventing type laundering through the evaluator.
A source-kind/status whitelist is scientist-authored policy, not evidence that a claim is true.

REVIEWED ADAPTERS

1. MolecularSanitizer.Result -> toolkit-chemical-validation@1, qualitative.
   Checks exact graph attribution; preserves backend name/version/operation, lineage, normalization
   changes and messages. Validity yields category 'valid', status SCREENING_ONLY. Invalidity or
   unauthorized meaningful normalization yields UNAVAILABLE with no usable value. Source validity
   remains explicit in limitations. No geometry, retained function or biological success is inferred.
2. FragmentInteractionCalculator.Result -> electronic-fragment-interaction-energy@1, hartree.
   Fixed Aether PBE-D3 counterpoise method/protocol; original receipt and component/cache/convergence
   details preserved. Requires the six distinct RHF/PBE CP roles, finite available energies, three
   dispersion receipts and no failures. Otherwise returns UNAVAILABLE/no value. SCREENING_ONLY
   survives; this is not free energy, affinity or potency. The point estimate has no uncertainty
   estimate: equal bounds do NOT assert zero physical uncertainty.

Both adapters require explicit review, subject/system/context association. They do not discover
or ingest arbitrary historical outputs. The Aether result does not itself encode the full ligand
DesignState: that association remains a reviewer responsibility, prominently recorded in limits.
Receipt hashes are source identifiers, not cryptographically authenticated by these adapters.
Per-run receipt details are provenance, not method parameters, so different receipts do not become
incomparable merely because they have different hashes. Underlying source algorithms are unchanged.

REVIEWED REGION BINDING

Exact parent + stable atom IDs remains available without a backend lookup. Rebinding requires
schema 2, one explicit ReviewedBinding, reviewer and grammar references, and the exact target state.
The reused EditableVector must identify the existing unique source site and ATOM_SUBSTITUTION.
Protected neighborhood atoms and retained atom/bond anchors are mapped, not guessed.
Unsupported hard/geometric/substituent-class restrictions decline instead of being ignored.

The injected existing CanonicalIdentityService supplies both identities and complete correspondence.
Backend/version and canonical keys must agree. Exactly one exhaustive mapping is required. Multiple
symmetry alternatives produce AMBIGUOUS_SITE; absent/truncated/incomplete mapping or missing backend
produces UNSUPPORTED_LINEAGE. Canonical identity by itself is insufficient. Mapping IDs must cover
both graphs bijectively; coordinates and metadata must remain unchanged under that mapping.
The backend owns chemical/stereo equivalence; the planner only checks applicability and state data.
Full proof and alternatives remain in the durable Decision, including declined correspondence.
Successful provenance includes knowledge snapshot, binding, grammar and reviewer references.

StableAtomOrbitService was considered but orbits deliberately group symmetry equivalents and cannot
prove unique lineage. Feature perception/attachment concepts were inspected but are not used to
select new sites. This slice transfers a reviewed existing region only; it does not search for motifs,
select among symmetric atoms, infer feature equivalence or transfer geometry between coordinate frames.
Real OCL rebinding is tested through the existing generator, transaction, validator and journal.

EVALUATION / REVISION

Schema-2 findings are recomputed against hypothesis-owned criteria on insertion/loading; a manually
strengthened conclusion cannot be inserted. Unknown criterion or observation references throw.
Absent criterion observations are NOT_MEASURED, not an invented measurement.
Wrong context/method/endpoint/system/conditions/unit/kind/state or unmet status qualification is
UNRESOLVED. Applicable failed/unavailable evaluations produce FAILED_INVALID, not contradiction.
For comparable usable numeric observations: an interval wholly within the accepted range SUPPORTS;
an interval disjoint from it CONTRADICTS; an overlapping boundary is UNRESOLVED. Qualitative equality
supports the specified category; a different comparable category contradicts it. Policies and their
sources are versioned in the snapshot; no hidden scientific thresholds are introduced.

Evaluation is a computational rule assessment; findings retain original source kinds and references.
Successful molecule construction and validation alone never create biological findings.
Evidence must match the attempted resulting derivation's graph, state ID, parent and provenance.
Representative storage-node ID is not the scientific applicability key; deduplicated derivations
retain their own graph/provenance under Phase 1. No cross-run global identity registry is introduced.

revise still requires an explicit reviewed observation and scientist-written new claim/consequence.
It preserves old hypotheses/evidence/receipts. Contradictions enter conflict references, all-support
observations enter support, otherwise unresolved observations are retained. Conflicts and unresolved
observations block automatic replanning. Reusing support also requires matching original criteria,
parent applicability and allowed raw evidence classes. No automatic promotion to truth occurs.

KNOWN LIMITATIONS / RECOMMENDED PHASE 2.3 (NOT STARTED)

- Qualification and reviewer/source attribution are explicit trusted inputs, not authenticated truth.
- Strict exact comparability; no conversions, assay ontology, effect-size statistics, confidence
  calibration, cross-system causal transfer or general biological-evidence importer.
- Legacy schema 1 intentionally retains Phase 2.1 semantics for replay, not Phase 2.2 guarantees.
- Region transfer is limited to unique backend-proven identity correspondence with unchanged
  coordinates/metadata. No ambiguity resolution, motif binding, conformer transfer or new placement.
- Human policy must interpret numeric intervals and uncertainty descriptions appropriately; the
  engine only implements explicit interval/category predicates, not statistical significance.
- Adapter audit details are preserved in method/source/limitations, not a new normalized archive of
  all source receipts. Raw receipt storage/authentication remains a host responsibility.
- Hosts must journal knowledge before planning and use durable decision/execution sinks. No new
  workflow/CLI is introduced. Semantic replay is tested, not canonical byte ordering across JVMs.
- Version uniqueness is snapshot-local. Cross-file ID reuse and independent review governance
  need a separate persisted registry/protocol before broader external evidence ingestion.

Recommend a narrowly reviewed evidence-ingestion checkpoint next: choose one real, target-independent
source/endpoint; define its review and attribution contract, unit/uncertainty policy and immutable
receipt storage; add end-to-end fixtures without widening transformation chemistry. Broader region
binding should wait for explicit ambiguity/coordinate-transfer requirements. WELD resources and
Hephaestus consolidation remain separate approvals. STOP here after the Phase 2.2 commit.
