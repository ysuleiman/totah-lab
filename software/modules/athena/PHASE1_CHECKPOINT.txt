Completed behavior and public contracts
MolecularGraph now owns structural validation and Delta. Full before/after snapshots preserve ordering,
metadata, element, isotope, charge, hydrogen annotation, aromaticity, stereo, coordinates, endpoints,
orders, additions and deletions. Atom chemical changes exclude coordinates, which have a separate list.
Replay requires the exact parent snapshot. Metadata changes remain conservatively visible as graph changes.
GraphEditReceipt and TopologyEditReceipt carry the same Delta, rather than competing change models.
Both existing transaction engines emit typed Rejected failures (AUTHORIZATION, TOPOLOGY, CHEMISTRY).

MolecularDesignTree owns Reference, RetainedAnchor, Provenance, DesignState, Attempt, Outcome and
Termination. References require IDs and versions. Provenance contains hypothesis, evidence, anchor,
authorized rule, resource and geometry-constraint references plus opaque design intent. An Attempt embeds
its entire parent design state, operation/authorization, raw and resulting graph states, edit receipt,
transaction/validation/final deltas, evidence, canonical key, representative correspondence, and composed
parent lineage. Scientifically different derivations keep distinct DesignStates even when sharing a Node.
No A/B, residue, compound, or target vocabulary enters these generic contracts.

MolecularDesignGraphGenerator.generateTraced is the shared bounded path, with a state-aware planner,
synchronous OutcomeSink and GeometryValidator. Existing graph/topology editors remain the only editors.
Every executed operation and every known queued operation blocked by a limit gets a receipt. Root and
planner failures are explicit. Backend evidence is required. Invalid topology is checked even when
multiple components are allowed. Sanitization cannot silently alter graph chemistry or stable ordering;
coordinate-only changes have their own delta and go through geometry evaluation. Requested constraints
must all be reported evaluated. Runtime failures become receipts; persistence I/O failures propagate.
Operation IDs can repeat under different hypotheses; execution IDs remain unique within a run.

CanonicalIdentityService owns Correspondence/Mapping and one bounded attributed-graph proof search.
It is not another canonical identity implementation. The default search checks element, isotope, formal
charge, hydrogen count, aromaticity, stereo, connectivity, bond order and endpoints, ignoring coordinates
and source metadata. All found symmetry alternatives are retained, with an exhaustive flag and visited
state count; caps are 100,000 search states and 256 mappings. Stable-ID order chooses a representative
mapping but does not assert unique physical atom lineage. Each alternative can compose the stored
parent-to-attempt mapping. Equal canonical keys without a graph proof produce LINEAGE_MAPPING_FAILURE.

OclMolecularBackend remains the concrete identity/sanitization authority. It proves canonical equality and
converts relative tetrahedral parity to OCL CIP labels before reusing the shared correspondence search.
Unknown/unresolved relative stereo fails closed. Explicit bond-stereo descriptors unsupported by the
mapper now fail rather than silently disappearing. Positive hydrogen annotations must match OCL's inferred
unrepresented hydrogens; zero retains the historical unspecified-count convention. These checks apply to
identity/sanitization, leaving historical force-field calculation behavior unchanged.

Durability
MolecularDesignTree.Journal is a concrete OutcomeSink using Athena's existing Jackson dependency.
Use try-with-resources and a fresh Path per run. It writes schema athena-design-journal/1 JSON lines for
started, state, planned, receipt and terminated events. Every event is FileChannel.force(true)'d before
execution advances. CREATE_NEW refuses overwrite. Receipts round-trip through Jackson and replay after
reading from disk. A planned event without a receipt, missing terminated event, or trailing partial line
indicates interruption; it must not be interpreted as successful completion. Automatic crash recovery,
resumption, multi-process appending and cross-run deduplication are not implemented. File durability is
subject to the host filesystem/hardware guarantees. Event JSON is versioned but not a canonical byte-hash
format; arrays preserve molecular order. Hosts may provide another transactional OutcomeSink.

Known limitations and Phase 2 implications
* Production callers must supply reviewed non-legacy provenance, a fresh durable journal (or transactional
  sink), bounded deterministic planner and appropriate geometry validator. Evidence/rule IDs and opaque
  intent are references, not a target-science approval engine. The host owns the run namespace.
* A planner returns a finite list; its own runtime/output size is not governed by an Athena timeout.
  Receipts cover known planned operations, not an infinite unenumerated search space. Geometry evidence
  is a caller-supplied assessment; this phase adds no placement/clash algorithms or scoring objective.
* Correspondence is conservative, bounded and potentially ambiguous. It does not equate tautomers,
  alternative aromatic encodings, unspecified versus positive H annotations, or unsupported stereo.
  Non-exhaustive alternatives do not establish unique lineage. Automatic stereo enumeration is rejected
  by this generation path even though historical direct topology operations expose that disposition.
* OCL validate() currently requires total charge balance. Net-charged molecules therefore receive a
  backend validation failure; the limitation is tested, not bypassed or hidden. Charge-balanced examples
  verify that individual formal charges survive generation and deduplication.
* Existing force-field behavior was not scientifically requalified. Positive H annotations in design
  validation are now checked, but this phase does not rewrite force-field hydrogen preparation.
* General E/Z bond-stereo encoding and normalization lineage are not implemented. A future resource
  provider must reject unsupported inputs or qualify extensions in OCL before enabling them.
* The legacy target gate remains architectural debt outside the generic design path. Architecture token
  checks cover known target concepts and dependencies, not semantic detection of every possible policy.

Phase 2 must remain a separate reviewed work unit. Resource integration can feed this single Java-native
path; WELD must not become a runtime dependency or another generator. Before enabling a resource class,
qualify its charge/H/stereo/aromaticity semantics and mapping behavior against OCL, search existing Java
owners first, and review unsupported cases above. No WELD resource, placement, SMIRKS, reaction, scaffold-
hopping or target-compound generation capability was enabled here. Stop at this checkpoint.
