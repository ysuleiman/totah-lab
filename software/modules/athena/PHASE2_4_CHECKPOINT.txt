OWNER AND REUSE

DAEDALUS PipelineFactory is the existing cross-module composition owner. Inspected Pipeline,
Stage, PipelineContext, PipelineRunDirectoryFactory, DaedalusCli and DefaultPocketEvidenceAssembler.
Docking stages and the pocket-specific evidence assembler do not own molecular-design review.
PipelineFactory.openDesignReasoningRun(identity) now creates a GovernedDesignWorkflow session.
The session is the only new production top-level class. It is needed to own a closeable durable
journal and a fixed registry across review, snapshot loading, planning and evaluation; the existing
factory is not itself a run/session and its docking Pipeline must not be repurposed. The constructor
is package-private. Existing factory workspace and run-directory allocation are reused.

No new generator, graph, candidate, canonicalizer, atom matcher, scientific scoring engine or module.
- Athena CanonicalIdentityService: existing Result/Correspondence and attributed-graph mapping search.
  completeFor centralizes existing planner coverage checks; associate composes existing services.
- OclMolecularBackend/OclGraphMapper: existing OCL parser, Canonizer and sole graph conversion boundary.
- DesignKnowledge: unchanged requirement, criterion, five-outcome evaluation and revision semantics.
- HypothesisDirectedPlanner: unchanged hypothesis authorization, apart from reusing completeFor.
- DesignGrammarJsonCodec: extended single existing immutable ID/version registry and snapshot codec.
- MolecularDesignTree.Journal: existing CREATE_NEW/forced writer, additive interpretation/failure events.
- Hermes PubChemMolecularWeightImporter: same source owner, receipt reconstruction, raw-byte hashes.
- METTL7 Mettl7EvidenceCatalog/Mettl7CompoundEvidence: existing observation source and interpretation owner.

New nested records extend existing owners rather than creating parallel models:
Association holds existing identity Results and Correspondence; SourceAssociation adds raw structural
capture/proof to SourceDecision; Interpretation carries an opaque reviewed downstream typed source,
policy and Evidence. PubChem's source-specific receipt cannot honestly represent an assay catalog.
There is no general assay importer or ontology and no target logic in these generic records.

ENFORCED NORMAL PROTOCOL

factory workspace / design-evidence-registry is fixed for every run from that factory. No operation
accepts a caller-selected registry. A distinct configured workspace is intentionally a distinct scope.

reviewPubChem:
1. Hermes imports the exact raw property bytes into a CREATE_NEW run-local receipt.
2. Hermes reparses/reconstructs that receipt; source errors stop before the reviewer callback.
3. Hermes verifies one matching positive CID and an isomeric-SMILES structural accompaniment.
4. An explicitly supplied reviewer callback supplies separate scientific relevance and state attribution.
5. The injected chemistry service decodes the source and proves identity/correspondence to that state.
6. Existing registry reserves the full accepted/rejected decision, including source and structural proof.
7. The forced journal records the review before returning the decision.

saveKnowledge/load/plan/evaluate/revise require qualified schema-2 knowledge and governed loading.
Every Evidence must equal its immutable reservation. For PubChem, every load reparses property and
structural raw bytes through Hermes and reproduces graph, identity and complete correspondence with
the injected backend; uncertified legacy reservations cannot enter the normal production path.
For downstream evidence, every load checks the reviewed Interpretation and exact Evidence reservation.
Reviews/interpretations are journaled before full knowledge; knowledge precedes planning/evaluation.
An evaluated snapshot journals its complete evaluation, including the original execution Attempt.
Failures during PubChem review/loading produce protocol-failure events; mismatch/truncated association
produces a durable rejected source decision. This is not a new universal failure/transaction framework.

Source reviews and downstream interpretations use the SAME ID/version namespace and CREATE_NEW
reservation writer. Conflicting cross-kind entries fail. Exact existing content is idempotent.
Legacy JSON without the new optional association property retains typed equality/idempotency.
No registry entry or snapshot is overwritten to recover an inconsistency.

MOLECULAR ASSOCIATION

Captured PubChem isomeric-SMILES responses for CID 702 (CCO) and 6343 (CCS) accompany the frozen
Phase 2.3 molecular-weight captures. STRUCTURE_CAPTURE.json records URLs, capture times and raw
SHA256 values. The original Phase 2.3 property captures are unchanged. Hermes performs no chemistry.

Injected CanonicalIdentityService.decodeStructure and associate reuse OCL identity and the existing
bounded attributed-graph correspondence. Acceptance requires matching backend/version/canonical key,
exhaustive correspondence, EXACTLY ONE alternative, and total bijective atom AND bond coverage.
Canonical equality alone, mass, name or CID alone cannot prove association. Multiple symmetry mappings,
truncation, unequal structures, unsupported/lossy representations or unavailable services fail closed.
The full attempted source-to-reviewed-state atom/bond mapping and alternatives are retained.

OCL decoding is deliberately SMILES-only in production. It has a fixed parser seed, maps through the
existing OclGraphMapper, validates connected topology and requires original-to-round-trip canonical
identity equality. External E/Z/bond stereo that the mapper cannot represent is rejected. Small-ring
bond parity is topology constrained and remains subject to the same canonical round-trip check.
Tests cover ordering, symmetry, isotope, charge, tetrahedral stereo, aromaticity and determinism.
Coordinates and metadata do not establish chemical identity, and no normalization-equivalence claim
is introduced. This source association is not design-state applicability transfer or physical lineage.

Decoding/certifying source identity is NOT sanitization or execution authorization. In particular,
OCL validate() rejects net ions and can reject a SMILES drawing's 2D stereo layout. The decoder does
not use that execution validator as an identity predicate. The existing MolecularSanitizer and all
execution validation behavior remain unchanged. Charged source identity is retained, not neutralized.
The old prepared TSL MOLFILE did not round-trip exactly in an exploratory check; arbitrary prepared
3D MOLFILE ingestion is excluded rather than silently weakening the canonical equality check.

LIMITS / RECOMMENDATION FOR PHASE 2.5

- This is an enforced factory session protocol, not a CLI command, server identity system or access-control
  boundary. Legacy APIs remain callable deliberately. Filesystem administrators and trusted code can
  write arbitrary registries; this implementation prevents accidental use, not hostile local tampering.
- The registry is shared per configured workspace, not global/distributed. A crash can leave a partial
  reservation that fails closed; there is no automated overwrite/recovery or cross-file atomic transaction.
- Raw hashes verify captured-byte consistency, not PubChem authenticity or immutable CID release history.
  The separate structural response has capture provenance, not a signed version or property/structure
  atomic snapshot. Molecular weight is never used as an identity proof.
- Downstream interpretations are reviewed trusted adapter output. Athena does not recompute METTL7 policy
  or prove manuscript/catalog truth. The selected assay subject binding remains explicitly reviewer supplied.
- Symmetry, unsupported E/Z and normalization-dependent correspondences decline. No broad chemistry fix,
  general SDF decoder or atom correspondence algorithm was introduced to force a real example through.
- Source identity certification does not certify valid chemistry, geometry, biological relevance or measured
  microstate; execution sanitizer and authorization remain mandatory. Scientific uncertainty remains explicit.

Recommend a separately approved Phase 2.5 to review deployment/application exposure of this factory
protocol, stronger source/reviewer attribution and a bounded downstream subject-binding policy. Characterize
unsupported charged/stereo/prepared-state semantics before expanding chemistry or ingesting fragment libraries.
Do not treat this observation or successful infrastructure tests as a license for a new inhibitor campaign.
