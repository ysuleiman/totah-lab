PROSPECTIVE CONTRACT — NOT IMPLEMENTED / NOT APPROVED
2026-10-06; N02/N03/N04/G08 and I20 prerequisite

Why a real contract boundary exists
InteractionFingerprint.of stores positive residue/type sets and raw interactions.
It has no evaluated event universe, missing-state mask or count identity.
RuleRequest binds one SystemStateView. An ensemble must not be invented by
reading all historical catalog records. Generic EvidenceEnvelope preservation
can carry bytes, but does not specify the meaning of ensemble selection.
Changing absent fingerprint bits into negative observations would change legacy
semantics. Leave the legacy class unchanged.

Smallest proposed integration
No Java public API additions. Use existing EvidenceEnvelope, direct-assessment
analyzers, Findings and governed evaluateCurrent path. No new graph, database,
matcher, geometry engine, research gate or implicit catalog lookup.
The following are new payload contracts and therefore require prospective
approval under the standing schema gate. They are not authorized by this file.

1. athena-typed-event-set/1 (explicit input evidence)
- schema; exact immutable system-state binding; selected source evidence refs
  with payload digests; exact profile/definition/implementation identity.
- declared finite event universe; each event key contains rule definition digest,
  ordered role-to-stable-entity correspondence and explicit directionality.
- role tuples use existing atom/group/entity references. No residue-name identity.
- correspondence alternatives remain separate; ambiguous equivalence never
  deduplicates distinct events silently.
- each event has independent attributed observations/statuses, original source
  refs/digests, and complete-scope coverage refs where a negative is asserted.
- distinguish SUPPORTED_PRESENT, ABSENT_FALSE, NOT_EVALUATED, UNSUPPORTED,
  UNKNOWN_INCONCLUSIVE, FAILED. Conflicting positives/negatives coexist and are
  unresolved for aggregation; no recency/precedence resolution.
- missing universe member is unknown, never zero. Positive-only legacy imports
  remain positive-only and cannot assert exhaustive negatives.

2. athena-event-analysis-plan/1 (explicit selection, not scientific thresholds)
- schema; exact operation; ordered explicit state bindings and input refs/digests;
  explicit event keys or exact member-event projection; correspondence map;
  optional explicit network start/end entity references and maximum path length.
- operations: EVENT_COUNTS, COOCCURRENCE_COUNTS, SIMPLE_PATHS, UNPAIRED.
- state identity is binding+source state digest. Repeated identical selection is
  idempotent; contradictory content for one identity fails without mutation.
- EVENT_COUNTS: return all selected states, resolved present, resolved absent,
  unevaluable and conflicting counts. eligible = present + absent. Fraction is
  exact numerator/denominator; undefined if eligible=0, never fabricated zero.
- Count multiplicity counts distinct event keys, not duplicate records or query
  automorphisms. Any coarser projection explicitly lists member event keys;
  presence is any resolved positive; absence requires all members resolved
  absent and complete enumeration; otherwise unresolved.
- COOCCURRENCE_COUNTS: use only explicitly corresponding common states where
  every selected event is resolved. Preserve all excluded-state IDs/reasons.
  Return exact contingency counts and joint numerator/denominator. No probability,
  causal correlation, pairing of independent ensembles or Pearson coefficient.
- SIMPLE_PATHS: one exact state; selected supported typed edges only; preserve
  edge direction. Enumerate simple paths with no repeated node, canonical order.
  Declared traversal bound is scope; truncation returns partial/inconclusive.
  No-path negative requires complete applicable edge coverage and exhaustive
  traversal in the requested scope. Path is not energy transfer or mechanism.
- UNPAIRED: explicit feature and universe of applicable partner events under one
  named profile; supported unpaired requires every event resolved absent plus
  exhaustive partner enumeration. Missing/unsupported events remain inconclusive.

3. athena-event-analysis/1 (immutable derived payload)
- schema; operation/plan digest; exact selected input refs/digests; implementation
  identity; state/correspondence bindings; deterministic event/state ordering;
  per-event/combination raw counts, masks/excluded IDs/reasons, exact fraction
  numerator/denominator or null, paths/edge provenance where applicable.
- assessment and complete/partial traversal status remain distinct from counts.
- source assertions are never overwritten. Future interpretation makes a new
  evidence record; existing provenance/gate/receipt policies remain unchanged.

Mandatory qualification after approval
Explicit-vs-inherited evidence; state/hash/definition mismatch; duplicate and
conflicting records; symmetry and mapping alternatives; zero eligible states;
missing vs false; asymmetric eligibility; exact co-occurrence counts; independent
ensembles not paired; directed/cyclic/path-bounded cases; positive-only legacy
imports; missing negative coverage; immutable source/read-back; tamper rejection;
permutation/deterministic independent-JVM replay; historical consumers unchanged.
No current-policy production receipt is fabricated by this engineering work.

N08 remains separate: pharmacophore feature/tolerance matching is not implied by
these event-count/path contracts. I12/I13 remain separate: a typed path contract
does not supply missing water chemistry or directional H-bond leg definitions.
