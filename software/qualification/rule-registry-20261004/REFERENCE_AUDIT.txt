Exact numeric thresholds and bound conventions for each family are in the respective
PLIP_3_0_1 manifest; scientific comments/citations remain in pinned config.py. Do not
apply a universal strict-bound convention: water distances are inclusive; amine guard
has its own comparison. Metal geometry uses angular-fit heuristics, not just 3 A.
The complete code is authoritative for ordering, special modes and exclusions.

Perception/preparation differences material to qualification:
- PLIP normally adds polar hydrogens; this frozen-state pipeline never does so.
- Original atom mapping and alternate-conformer filtering affect candidate identity.
- PLIP ring membership/normal construction differs from Athena chordless-cycle and
  least-squares-plane methods. Equal numerical thresholds do not imply equal results.
- PLIP functional-group heuristics are not a proof of a biological ionization state;
  the Java registry requires authoritative formal-charge coverage for negative claims.
- Binding-site atom selection, ligand definitions and DNA/peptide/intra modes are
  separate upstream policies. Full system graph ownership remains unchanged here.
See the exact pinned source rather than replacing its behavior with method names.

C. OpenFF / SMIRNOFF architectural reference
Source: https://openforcefield.github.io/standards/standards/smirnoff/
Captured as reference/openff-smirnoff.html (content hash pinned).
Relevant architecture: chemical pattern matching, declared aromaticity model, versioned
serialization, units and ordered specificity/assignment. Its later-match precedence
belongs to parameter assignment, not universal scientific conflict resolution.
Existing OCL matcher already provides SMARTS matching and stable query-to-target atom
IDs with backend evidence. New matcher, SMARTS dialect or force-field assignment is
unnecessary. OCL semantics are not silently labeled OpenFF/OpenEye semantics.
Here profiles assess independently; conflicts coexist. No global last-rule-wins.
Existing native refinement order is method-specific and retains raw detections.
No SMIRNOFF force constants, charging model, energy function or parameterization added.

D. MolProbity / Probe architectural reference
Source: https://github.com/rlabduke/probe/blob/master/README.probe.txt
Captured as reference/probe-readme.txt. Upstream deprecates this legacy Probe in favor
of CCTBX Probe2; no assertion that Athena implements either program.
Probe examines atom-surface contacts with explicit H and defined radii/preparation;
its dot-based contact classification is not the native heavy-atom overlap algorithm.
Keep a reference radii/ideal-geometry dataset, its source and its validation algorithm
separately attributable. This milestone pins Gaia's current radii table separately
from StericClashAnalysis. It does not import Probe radii or qualify ideal-geometry checks.
Changing a numerical radius/algorithm requires new method/reference provenance;
matching one cutoff alone cannot establish MolProbity/Probe validation equivalence.

F. Algorithm details and parity limitations
reference/ALGORITHM_REQUIREMENTS.json is included by digest in every external profile.
It records the per-family perception, geometric construction and refinement prerequisites.
Additional common policies: config BS_DIST=7.5 A is an upstream preselection parameter,
not permission for a derived Pocket to remove evidence from the full system graph.
Alternate conformers, original atom mapping, ligand extraction, model/chain/region modes
and polar-H preparation must be pinned before any future exact-parity qualification.
The INTRA filter additionally removes same-residue contacts and deduplicates unordered
residue pairs using rounded distances; this is not Athena's full-identity refinement.

Actual code differs from shorthand chemical descriptions in places. For example,
is_functional_group compares string '1' with integer neighbor atomic numbers; metal
alcohol perception also counts string '1'. Water refinement's replacement path stores
an angle where other entries store distance from 110 degrees. Ring normals come from
selected ordered atoms, not a fitted plane. Exact-code parity would have to preserve or
explicitly version such behavior; none has been silently fixed or ported here.
Metal fitting uses mean Euclidean norms of matched angular residuals, rather than an
energy or a conventional normalized RMS deviation. Single-target geometry is NA;
coordination candidates are 2-6. The source's 0.5/3.5 selection heuristics are retained
with angular-score units and the full algorithm reference, not treated as distances.
