4. Reconstruction / exact arithmetic specification
All source coordinates are Angstrom binary64 values. Fixed ordered tuple N,CA,C,CB.
Parameter order: dist, angleCAB, dihedralNCAB, angleNAB, dihedralCNAB, angleideal.
 SER: 1.530, 110.1, 122.8, 110.5, -122.6, 111.2.
 THR/VAL: 1.540, 109.1, 123.4, 111.5, -122.0, 111.2.
angleideal is retained for source traceability; upstream does not use it in this
reconstruction. Do not add an angleideal eligibility test.

Preserve the expression/operation order of pinned construct_fourth for NCAB
then CNAB and pinned rotate_point_around_axis, using Java21 strict binary64,
StrictMath.sin/cos/sqrt, Math.PI and left-to-right sums. x**2 is x*x; dlsq**0.5
is StrictMath.sqrt(dlsq). Cross products preserve the pinned operand order.
No FMA, reassociation, intermediate decimal rounding or alternate orthogonalizer.

NCAB uses res0=N,res1=C,res2=CA; CNAB uses res0=C,res1=N,res2=CA.
In each construction a=res2-res1, b=res0-res1, c=a cross b.
Normalize c to dist, add res2, rotate about res1->res2 by dihedral-90 degrees
using the pinned rotation formula. Recompute a=newD-res2, b=res1-res2,
c=a cross b; normalize c to dist; rotate newD about res2->(res2+c) by
90-angle degrees. These two resulting points are betaNCAB and betaCNAB.
Mean=(betaNCAB+betaCNAB)/2; betadist=norm(CA-Mean).
If betadist != dist, reference=CA+(Mean-CA)*dist/betadist in that order;
otherwise reference=Mean. deviation=norm(sourceCB-reference).
Vector norm sums x*x then y*y then z*z and applies StrictMath.sqrt.
The reference point is COMPUTED_REFERENCE_POSITION, never an observed atom,
new source-graph member, H coordinate or preparation mutation.

Numerical profile ID: ATHENA_JAVA21_STRICT_BINARY64_CB_RECONSTRUCTION/1.
This is a declared native arithmetic profile of the pinned uncorrected algorithm.
Do NOT claim bit-identical coordinate-to-deviation cctbx parity: Python libm and
Java StrictMath may differ. Retain those differences, with no invented tolerance.
Category comparisons against upstream are exact when given the SAME resulting
binary64 deviation. Independent upstream coordinate fixtures characterize the
algorithm; any categorical disagreement must be recorded and reviewed, not
accepted by widening a tolerance. Exact JVM replay remains required.

5. Degeneracy choice requiring approval
Pinned construct_fourth normalizes only if cmag > 0.000001, otherwise it continues
with the unnormalized vector. Review probes show a finite ideal/deviation for a
tiny nonzero normal, None for a collinear case, and ZeroDivisionError for a zero
axis. These are actual upstream outcomes, not hypothetical claims.
Recommended bounded Athena policy: require BOTH normalization guards in BOTH
constructions to satisfy the exact source condition cmag > 0.000001. Otherwise
UNKNOWN and no ideal point/deviation/category. Also require each rotation axis
squared norm and final betadist to be finite and >0, and all intermediates finite.
No new numerical guard constant is introduced; 1e-6 comes from pinned source,
but refusing the unnormalized branch IS an explicit narrower-domain choice.
It must not be called exact upstream degeneracy parity. The alternative faithful
unnormalized continuation is defensible but is not this recommended contract.
Undefined optional reference-to-observed CB orientation is not needed: this first
payload omits that extra torsion entirely. No change to existing Athena DIHEDRAL.
