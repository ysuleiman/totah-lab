SMALLEST ADDITIVE I03-A SCIENTIFIC PAYLOAD CONTRACT — APPROVAL REQUIRED
No implementation, RuleManifest, API method or schema registration is added now.
No inferred-H AtomReference, molecular graph atom, plane engine or virtual-site
framework is needed for the recommended real-heavy-atom proxy.

Proposed input evidenceType athena:implicit-h-proxy-plan
JSON exact top-level fields:
 schema: "athena-implicit-h-proxy-plan/1"
 stateBinding: existing full SystemStateView binding
 donorAtoms: nonempty array of existing AtomReference, canonical sorted, unique
 acceptorAtoms: nonempty array of existing AtomReference, canonical sorted, unique
 artifacts: array of existing {reference,sha256} envelope pins
 hybridizationEvidence: array of selected existing {reference,sha256} envelope pins
 inventoryCoverage: array of existing {reference,sha256} envelope pins

Each selected hybridizationEvidence payload is an existing EvidenceInterpretation
record, with existing inputs pinning the underlying source report and exact
perception/preparation protocol bytes. Its measurements require these scientific
keys (all strings, retaining the existing Java model):
 proposition = SOURCE_ATOM_HYBRIDIZATION
 stateBinding = canonical JSON of the complete bound state
 atom = canonical JSON of the source AtomReference
 hybridization = SP3 (or an explicit unsupported/unknown source value)
 assignmentProtocol = canonical JSON of {reference,sha256}, resolved among inputs
The evaluator identifies the actual assignment method/version. Method identity,
source report, graph/preparation/sanitization options, applicable current-policy
review and reported assignment must agree. SUPPORTED_PRESENT alone is not a
substitute for applicable assignment qualification. Raw third-party output cannot
be made authoritative just by wrapping it in an interpretation. No new trusted
issuer, default RDKit version or inferred source qualification is invented.
Different independent assertions with incompatible values remain conflicting;
exact duplicates are idempotent; same-identity changed bytes are integrity errors.
An implementation must expose unresolved annotation applicability as unknown.
The exact annotation producer/protocol must be selected and independently
qualified before any production activation; this package selects none silently.

Inventory assertions reuse existing COMPLETE_EVENT_SCOPE with eventScope = SHA256
of canonical JSON {definitionSha256,stateBinding,donorAtoms,acceptorAtoms,
classPairs,assignmentProtocolPins}. classPairs is the exact six ordered pairs
from EXACT_ROLE_REUSE.json / I03_CONTRACT.txt. Coverage inputs independently bind
the source inventory and selection protocol. This proves only exhaustiveness;
not role identity, implicit H count, hybridization, directional validity or
current scientific support. Missing required chemistry and all possible in-domain
N occurrences in the selected atom scopes remain visible to negative coverage.
All heavy neighbors are recovered from complete source topology, never manually
selected to improve the minimum angle. Selection omitted outside-scope atoms
must not become a whole-state claim. Request radius cannot silently prune tuples.
Unknown fields, malformed pins, foreign-state inputs and duplicate atom identities
fail input integrity. Donor/acceptor scopes must be disjoint; selecting the same atom on both sides
is a malformed plan. Cross-component restrictions still apply.

Proposed output evidenceType athena:rule-measurements, existing envelope carrier.
JSON exact top-level fields:
 schema: "athena-implicit-h-proxy-measurements/1"
 definitionSha256: full selected manifest hash, distinct from I02
 stateBinding: exact input state binding
 plan: existing input envelope pin
 inputPins: explicitly consumed envelope pins
 geometryKind: "HEAVY_ATOM_DIRECTIONAL_PROXY"
 candidates: array of tuple records below
 complete: boolean for exact declared profile scope
 assessment: existing EvidenceInterpretation.Status name
 reasons: string array
 limitations: string array

Each candidate exact fields:
 donor, acceptor: existing AtomReference
 donorClass, acceptorClass: exact selected role IDs
 roleOccurrencePins: source role report/occurrence attribution
 hybridizationPins: selected assignment interpretation pins
 donorNeighbors, acceptorNeighbors: complete source heavy-neighbor AtomReference arrays
 geometry: existing raw continuous-geometry plan/results (DISTANCE and ANGLE only)
 donorMinimumDeviationDegrees, acceptorMinimumDeviationDegrees: qualified finite
   numbers or null with reasons; no substituted zero for missing values
 geometryKind: "HEAVY_ATOM_DIRECTIONAL_PROXY"
 assessment, reasons: existing status name and string array
No hydrogen, H-A, DHA, hydrogen coordinates, hydrogen orientation confidence,
probability, energy, radii or observed-H field exists in this payload.
Tuple identity binds state, definition, ordered class/atom pair, source occurrence
and assignment protocol identities; retain full neighbor witnesses. Different
preparations, role occurrences and definitions do not collapse silently.

Replay must recompute source roles, complete-neighbor inventories, geometry and
predicate from explicitly selected pinned evidence; measurements are not authority.
Collecting raw candidates is separate from current-policy scientific evaluation.
New schema names and scientific measurement keys need explicit approval before
implementation. Existing generic carriers can hold them without a public Java
signature change. No evaluator may consume this payload as I02 or I12/I13 evidence.

I03-B inferred-site representation is deliberately NOT specified as an approved
schema: choosing a placement/alternative policy precedes final site/uncertainty
fields. The conceptual minimum would separately bind a model site to donor,
anchors, parent state and preparation protocol, with unambiguous modeled origin
and alternate-site identity. Whether a new site payload or an existing prepared
SystemStateView is appropriate depends on that choice. No generic framework is
justified before the concrete scientific representation is selected.
